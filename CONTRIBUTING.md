# Участие в проекте

Спасибо за помощь с неофициальными часами «Время» для macOS. Перед изменениями прочитайте [README](README.md), [область MIT](LICENSE_SCOPE.md) и [правила общения](CODE_OF_CONDUCT.md).

## Сообщения об ошибках и предложения

Используйте формы Issues. Для ошибки укажите версию приложения, macOS, Apple Silicon/Intel, тему и шаги воспроизведения. Скриншоты и фрагменты логов добавляйте только после удаления личной информации.

Уязвимости сообщайте по [SECURITY.md](SECURITY.md), без публикации деталей в обычном Issue.

## Локальная работа

Требуются macOS, Swift 6 через Command Line Tools или Xcode, Node.js 22+ и npm.

```sh
npm ci
npm run build:preview
npm test
npm run build -- --reuse-artwork
```

Последняя команда собирает arm64 и x86_64, проверяет нативные сценарии и экспорт PNG и создаёт локальное ad-hoc приложение. При изменениях исходной графики используйте полную `npm run build` без `--reuse-artwork`. Сборка использует сохранённые мастера и не вызывает AI.

JavaScript-тесты можно запускать на Linux после `npm run build:preview`. Проверки AppKit требуют macOS с доступным оконным сеансом; они создают скрытые окна и не захватывают экран. Тесты не должны регистрировать автозапуск или менять настройки пользователя: для записи настроек используйте изолированный тестовый домен.

## Изменения кода

- Правьте исходники, а не `preview.js`, `themes-data.mjs` или `dist/`.
- UI и системная интеграция AppKit должны оставаться на `@MainActor`. Системные уведомления доставляйте в main queue.
- Сохраняйте единый формат тем, 12/24-часовые циклы и направление движения. Не меняйте bundle identifier без плана переноса пользовательских настроек.
- Для исправления поведения добавляйте содержательный регрессионный тест. Для небольших текстовых правок достаточно проверки результата.
- Не добавляйте ключи, сертификаты, токены, `.env`, кэши и готовые сборки в Git.

Не добавляйте сторонние изображения, логотипы, шрифты или другие материалы без указания источника и проверенных условий распространения. Промпт генерации не заменяет проверку прав на исходный референс. Документируйте происхождение графики в `THIRD_PARTY_NOTICES.md` и рядом с мастерами.

## Pull request

Описывайте проблему, итоговое поведение и выполненные проверки. Для изменений интерфейса приложите изображение с примером и перечислите проверенные версии macOS/архитектуры. Если ручная проверка не выполнена, укажите это прямо. Отдельно отмечайте изменения лицензий, графики, формата ресурсов и пользовательских настроек.

Ваш оригинальный код и документация предлагаются по MIT, если явно не согласовано иное. Не включайте материалы, на которые у вас нет необходимых прав. Соблюдайте существующие уведомления об авторских правах.

## CI

[Workflow](.github/workflows/ci.yml) проверяет Node.js на Ubuntu и полную нативную сборку на `macos-15` (Apple Silicon) и `macos-15-intel` (Intel). Обе сборки — universal, с минимумом macOS 13. CI на macOS 15 не заменяет ручную проверку macOS 13.

CI использует ad-hoc подпись, не требует секретов и не публикует приложение. В артефакты попадают только текстовый журнал и JSON-отчёт. Любые изменения Actions проверяйте `actionlint`; закрепляйте Actions полными SHA и обновляйте их через Dependabot.
