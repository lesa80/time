# Подготовка к публикации на GitHub

Публичный репозиторий — [lesa80/time](https://github.com/lesa80/time), основная ветка — `main`. Репозиторий создан, первый push выполнен 18 октября 2026 года. Первый коммит — `398e70c`.

Локальная ветка `main` отслеживает `origin/main`, `origin` настроен на `https://github.com/lesa80/time.git`. Автор первого коммита — `lesa80 <bolt42app@gmail.com>`: публичный email предоставлен владельцем, имя соответствует GitHub-логину. Настройка автора действует только в этом репозитории.

## Выбранный состав

Для публичной версии выбран полный набор из 25 тем: четыре варианта «Минимализма» и 21 тема «Ракеты». По заявленному назначению приложение не используется в коммерческих целях. Этот выбор не меняет MIT для кода и отдельный статус графики в [LICENSE_SCOPE.md](../LICENSE_SCOPE.md).

Автор проекта, GitHub @lesa80, подтвердил права на логотип БОЛТ42 и иконку «Время» и разрешил их публикацию в репозитории и готовом приложении с сохранением прав за собой. Условия — [assets/branding/RIGHTS.md](../assets/branding/RIGHTS.md). Эти изображения не перелицензируются по MIT.

Изображения производителя взяты из открытых источников и переработаны; в `reference/` также сохранены исходные фотографии. В проекте пока не зафиксирована лицензия или разрешение, подтверждающие их публичное распространение. Открытая доступность, переработка и некоммерческое назначение сами по себе не являются таким разрешением. Источники и способы подготовки уже перечислены в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) и файлах атрибуции; эти уведомления необходимо сохранить.

## Перед первым push

1. Прочитайте [LICENSE_SCOPE.md](../LICENSE_SCOPE.md) и [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). Разрешение на распространение картинок должно охватывать репозиторий, коллаж README, иконку и готовое приложение. Если разрешений нет, подготовьте отдельную сборку с доступными материалами и адаптируйте тесты. Исключение из MIT не является разрешением на публикацию.
2. Проверьте имя и email автора коммитов; при необходимости выберите GitHub noreply-адрес. Не добавляйте `.env`, сертификаты и ключи подписи, пользовательские файлы и логи. `.gitignore` уже исключает распространённые форматы секретов и производные сборки.
3. Проверьте локальные команды CI:

   ```sh
   npm ci
   npm run build:preview
   npm test
   npm run build -- --reuse-artwork
   ```

4. Если Git ещё не инициализирован, создайте репозиторий с выбранной основной веткой и проверьте список файлов перед коммитом. CI автоматически работает для `main` и `master`, pull request и ручного запуска; для другой основной ветки обновите workflow.
5. Не отправляйте `dist/` и `macos/.build/` в Git. ZIP приложения больше 100 МиБ, его место — в Releases. Графику при необходимости можно перевести на Git LFS; сейчас LFS не включён, и обычного clone достаточно для имеющихся ресурсов.

## После создания репозитория

- GitHub Actions и Dependabot запущены первым push. При проверке публикации задания стояли в очереди; итоговые результаты смотрите в [Actions](https://github.com/lesa80/time/actions). Локальные проверки не заменяют результаты runner GitHub.
- Включите private vulnerability reporting, проверьте инструкцию в [SECURITY.md](../SECURITY.md) и при желании добавьте подтверждённый приватный контакт.
- Проверьте secret scanning/push protection и Dependabot. Файл `dependabot.yml` задаёт еженедельные обновления npm и Actions; автоматическое слияние не включено.
- Защитите основную ветку правилами репозитория: review pull request и успешные проверки `JavaScript and raster resources`, `macOS / macos-15`, `macOS / macos-15-intel`. Настройки GitHub не изменяются добавлением файлов в каталог проекта.
- В README добавлены реальные ссылки на репозиторий, Actions и Releases. Тестовая сборка 2.4.4 доступна в [Releases](https://github.com/lesa80/time/releases/tag/v2.4.4): универсальный ZIP с приложением и SHA-256.

## Что делает CI

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml) запускает:

- Ubuntu 24.04 / Node.js 22: установка по lock-файлу, подготовка браузерного bundle и JavaScript-тесты.
- macOS 15 Apple Silicon и Intel: универсальная сборка, Swift 6, нативные проверки, проверка подписи и сравнение 59 экспортов PNG с независимым эталоном для текущих 25 тем.

Workflow использует `contents: read`, checkout без сохранения credentials, точные SHA официальных Actions и обычный `pull_request`. Developer ID и нотариализация в CI не используются; секреты не требуются. Есть ограничения времени и отмена устаревших запусков.

Сборки CI временные, с ad-hoc подписью. В GitHub artifacts отправляются только `macos-build.log` и `validation.json` на 7 дней. Приложение, архив, изображения и референсы автоматически не выкладываются в Releases или Pages.

Проверки AppKit создают скрытые окна и требуют доступного оконного сеанса. Они не захватывают экран и не меняют автозапуск. Если инфраструктура runner не даёт оконный сеанс, нужно выбрать подходящий macOS runner, а не незаметно пропускать эти тесты.

## Тестовая сборка приложения

Выбран тестовый релиз с локальной ad-hoc подписью, без Developer ID и нотариализации Apple. Условия подписи нужно явно указать в описании релиза; наличие успешных тестов не означает нотариализацию. Описание текущей тестовой сборки — [RELEASE_NOTES.md](RELEASE_NOTES.md).

- Проверьте права на все распространяемые материалы.
- Согласуйте `package.json` и lock-файл, `CFBundleShortVersionString` и `CFBundleVersion`, обновите [CHANGELOG](../CHANGELOG.md). Для текущей локальной версии это 2.4.4 / 2.4.4 / 27.
- Выполните ручные проверки автозапуска, меню, VoiceOver, нескольких мониторов и минимальной macOS 13. CI на macOS 15 не проверяет совместимость исполнения на macOS 13.
- При наличии Developer ID соберите с `VREMYA_SIGN_IDENTITY`, выполните нотариализацию и stapling по README, затем перепакуйте ZIP. Без этих шагов явно обозначьте архив как ad-hoc и ненотариализованный.
- Проверьте наличие `Contents/Resources/Legal/` и целостность архива. Сохраните MIT и уведомления об исключённых материалах.
- Приложите ZIP и SHA-256 к вручную созданному релизу, перечислите проверенные системы и ограничения. Автоматическая публикация в этом проекте не настроена.
